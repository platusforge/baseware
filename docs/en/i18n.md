# Internationalization (i18n)

The web app ships with a typed, zero-dependency i18n engine. **English is the source of truth and the fallback**; **pt-BR** is included as a complete second locale.

## Catalogs

| File | Purpose |
|---|---|
| `web/src/i18n/messages/en.ts` | Every key (source of truth) |
| `web/src/i18n/messages/pt-br.ts` | Must cover every English key — the build fails if one is missing |
| `web/src/i18n/index.ts` | Types, interpolation, plurals, detection/persistence, locale helpers |

Values are either a string or plural forms:

```ts
membersCount: { one: "{{count}} member", other: "{{count}} members" },
```

## Usage

```tsx
const { t, lang, setLang, languages } = useI18n();

t("members");                          // "Members"
t("membersCount", { count: 3 });       // "3 members"
t("sortBy", { column: "Email" });      // "Sort by Email"
```

- `{{name}}` tokens are interpolated; unknown tokens stay visible to catch typos.
- Plural forms are selected with `Intl.PluralRules` for the active locale (driven by `params.count`).
- Missing keys fall back to English, then to the key itself (with a dev warning).

## Language switching

`LanguageSwitcher` (`components/language-switcher/`) has two variants:

- `menu` — native `<select>` with full language names (dashboard sidebar).
- `toggle` — cycles to the next language; `iconOnly` for rails/topbars (public header, auth pages, mobile topbar).

The preference is stored in `localStorage` (`lang`) and mirrored to `<html lang>`. First visits follow the browser language (`pt*` → pt-BR, otherwise English).

## Formatting

Locale-aware helpers:

```ts
formatDate(date, lang);                    // "October 15, 2026" / "15 de outubro de 2026"
formatDateTime(date, lang);
formatNumber(1234.5, lang);
formatCurrency(49, "usd", lang);           // "$49.00" / "US$ 49,00"
```

## API errors

The API is locale-agnostic (English messages + HTTP status). `utils/api-errors.ts` maps known user-facing messages to catalog keys:

```ts
translateApiError("Invalid credentials.", t, "loginFailed");
```

Unknown messages pass through unchanged, so nothing is silently hidden.

## Tables and component labels

`DataTable` is context-free by design, but accepts localized labels. Use the hook:

```tsx
const tableLabels = useDataTableLabels(); // data-table labels from the active locale
<DataTable columns={columns} data={rows} keyOf={...} labels={tableLabels} />
```

The same pattern applies to `SearchBar.clearLabel`, `Modal.closeLabel`, `Drawer.closeLabel` and `Pagination.labels`.

## Adding a language

1. Copy `messages/en.ts` to `messages/xx.ts` and translate the values (keep every key).
2. Extend the `Lang` union in `i18n/index.ts` and register the catalog in `MESSAGES`.
3. Add an entry to `LANGUAGES` (`code`, `label`, `short`, `locale`).
4. If the browser detection needs a custom rule, extend `detectLang`.

> E-mails are still English-only in the starter. To localize them, persist the user's locale (e.g. a `locale` column) and render templates per language.
