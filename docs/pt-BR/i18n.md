# Internacionalização (i18n)

O app web vem com um motor de i18n tipado e sem dependências. **Inglês é a fonte da verdade e o fallback**; **pt-BR** é o segundo idioma completo incluído.

## Catálogos

| Arquivo | Papel |
|---|---|
| `web/src/i18n/messages/en.ts` | Todas as chaves (fonte da verdade) |
| `web/src/i18n/messages/pt-br.ts` | Precisa cobrir todas as chaves do inglês — o build falha se faltar alguma |
| `web/src/i18n/index.ts` | Tipos, interpolação, plurais, detecção/persistência, helpers de locale |

Valores são strings ou formas plurais:

```ts
membersCount: { one: "{{count}} membro", other: "{{count}} membros" },
```

## Uso

```tsx
const { t, lang, setLang, languages } = useI18n();

t("members");                          // "Membros"
t("membersCount", { count: 3 });       // "3 membros"
t("sortBy", { column: "E-mail" });     // "Ordenar por E-mail"
```

- Tokens `{{nome}}` são interpolados; tokens desconhecidos ficam visíveis para pegar erros de digitação.
- Formas plurais são escolhidas com `Intl.PluralRules` no locale ativo (a partir de `params.count`).
- Chaves ausentes caem para o inglês e depois para a própria chave (com aviso em dev).

## Troca de idioma

`LanguageSwitcher` (`components/language-switcher/`) tem duas variantes:

- `menu` — `<select>` nativo com nomes completos (sidebar do dashboard).
- `toggle` — alterna para o próximo idioma; `iconOnly` para trilhos/topbars (header público, páginas de auth, topbar mobile).

A preferência fica em `localStorage` (`lang`) e é refletida em `<html lang>`. A primeira visita segue o idioma do navegador (`pt*` → pt-BR, senão inglês).

## Formatação

Helpers cientes de locale:

```ts
formatDate(date, lang);                    // "October 15, 2026" / "15 de outubro de 2026"
formatDateTime(date, lang);
formatNumber(1234.5, lang);
formatCurrency(49, "usd", lang);           // "$49.00" / "US$ 49,00"
```

## Erros da API

A API é agnóstica de locale (mensagens em inglês + status HTTP). `utils/api-errors.ts` mapeia mensagens conhecidas para chaves do catálogo:

```ts
translateApiError("Invalid credentials.", t, "loginFailed");
```

Mensagens desconhecidas passam sem tradução, então nada fica escondido silenciosamente.

## Tabelas e labels de componentes

O `DataTable` é livre de contexto por design, mas aceita labels localizados. Use o hook:

```tsx
const tableLabels = useDataTableLabels(); // labels do data-table no idioma ativo
<DataTable columns={columns} data={rows} keyOf={...} labels={tableLabels} />
```

O mesmo padrão vale para `SearchBar.clearLabel`, `Modal.closeLabel`, `Drawer.closeLabel` e `Pagination.labels`.

## Adicionando um idioma

1. Copie `messages/en.ts` para `messages/xx.ts` e traduza os valores (mantenha todas as chaves).
2. Estenda a união `Lang` em `i18n/index.ts` e registre o catálogo em `MESSAGES`.
3. Adicione uma entrada em `LANGUAGES` (`code`, `label`, `short`, `locale`).
4. Se a detecção do navegador precisar de regra própria, estenda `detectLang`.

> E-mails ainda são só em inglês no starter. Para localizá-los, persista o locale do usuário (ex.: coluna `locale`) e renderize templates por idioma.
